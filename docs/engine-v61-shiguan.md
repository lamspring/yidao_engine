## 〇、第一性原理与边界

### 0.1 作者第一性原理

**史官只能翻译已发生的因果，不得发明因果。**

世界（yidao_core + 灵体层）负责"发生什么"。史官负责"把已发生的事说成人能读的故事"。史官的任何一句话，都必须能回溯到事件簿里的一条真实记录。说不出来源的句子，就是虚构，就是污染。

### 0.2 世界不解释自己，世界只留证据（draft-2 新增公理）

事件文本里的 `（因：饥饿+好斗）` 这类括号注释是**写死的标签**，不是从实况算出的因果——它既是"机械感"的来源，也是认识论上的越界（观测者不该被喂 motive，该靠调查得到 motive）。

**本条起：世界的事件只报告" observable 的行为与结果"，不附解释。** 因果信息以**结构化现场读数**的形式随事件存证（§2.2），叙事层默认看不见，史官需要时经调查接口调阅（§2.4）。

### 0.3 史官在演化回路之外

```
┌─────────────────────────────────────┐
│  世界层（yidao_core + 灵体）          │  ← 唯一真源，确定性，守恒
│  只存此刻。不存史。不解释。            │
└──────────────▲──────────────────────┘
               │ on_event 回调（只读订阅）
               │ snapshot() / 观心字段（只读）
┌──────────────┴──────────────────────┐
│  客户端层（史官）                     │
│  记录仪 → 事件簿（行为+现场读数+静默日常）│
│  调查接口 → 记忆档案 / 旁证链（按需调取） │
│  选链器 → 可讲述性报告（纯规则，零LLM）  │
│  成篇器 → LLM 翻译 + 考据表            │
│  校验器 → 锚定检查 + 虚构扫描           │
└─────────────────────────────────────┘
```

**硬性边界（违者即废）**：
1. 史官全链路**零写入内核**。只允许调用只读 API：`Session.genesis/run/snapshot`、`on_event` 订阅、灵体对象只读字段。
2. **世界不跑，史官不花钱**。LLM 调用只发生在成篇环节；记录、调查、选链、校验全部纯规则，零 LLM 成本。
3. 世界层为史官可做的改动**仅限观测性改造**（draft-2 批准的三件：去括号注释、事件挂现场读数、静默日常入簿——见 §2.5）。任何动力学改动（能量为司机）走 §十 的门禁，不在本需求书各期内夹带。

## 一、史官定位：侦探，不是解说员

史官是**全知但克制的史记作者**，其全知以"调查"为路径，不以"被喂"为路径：

- **看见的是行为**：事件簿里只有"石根抢夺了桑的土豆"这类干净记录，没有动机注释。
- **动机靠调查**：史官判断某事件值得深挖时，经调查接口调取三件套——
  1. **现场照片**：该事件的结构化现场读数（pressure 实值、阳余量、铭记时长等，§2.2）；
  2. **当事人记忆**：重要事件当 tick 的观心快照 + 事后仍可查的灵记忆档案（§2.3）；
  3. **旁证链**：事件簿中与当事人相关的先行事件（"他此前九日无渔获""第 5 日曾被夺屋"，§2.4）。
- **查不到就如实写"不可考"**：记忆会遗忘压缩，旧案证据可能已随时间湮灭——**真相随死者入土是史学的常态，不是缺陷**。冤案之所以是悬案，正因为证据死了。侦探查不到时，史官写"其因已不可考"，这比任何编出来的动机都有分量。
- **克制**：全知只用于反讽与留白（"他不知道，真凶另有其人"），绝不用于发明。
- **文体**：史记体 × 悬疑叙事的克制白描。短句。冷笔。戏剧性交给事实的排列，不交给形容词。禁用网文腔，禁用空泛抒情。

## 二、记录仪：事件簿 + 现场读数 + 观心快照 + 调查接口

> 位置：`v6/shiguan/recorder.py`（S1 已建，本期扩展）
> 依据：`Session.genesis(..., on_event=ledger.record)`；`on_event(tick, pos, text, kind, actor=None, target=None, **extra)`。

### 2.1 事件簿（EventLedger）（S1 已落地，本期两条修订）

1. **text 必须为去注释后的干净行为记录**（依赖 §2.5 世界层改造）；考据表回指以干净文本为准。
2. 新增 `readings` 字段（见 §2.2）与 `quiet` 标记（静默日常事件，见 §2.3）。

事件结构（draft-2 版）：

```python
{
  "tick": int, "day": int,
  "pos": tuple | None,
  "kind": str,
  "actor": str | None,
  "target": str | None,
  "text": str,              # 干净的行为记录，无任何"（因：…）"注释
  "readings": dict | None,  # 现场读数（§2.2），无则 None
  "quiet": bool,            # 静默日常事件（§2.3）：存簿但不进报告、不进链
  "extra": dict,
}
```

原要求不变：原样存录、JSON 可存取、同种子双跑逐字节一致、按 kind/actor/target/时间窗可查。

### 2.2 现场读数（SceneReadings）（draft-2 新增，替代"能量曲线"方案）

**决策在案**：不记连续能量轨迹（监控录像），只随事件存**发生当刻的能量读数**（现场照片）。理由：触发值（pressure=1.02、阳余 31、铭记 18 日）**就是事件本身的一部分**——"发生了什么"的完整答案本来就包括"在什么能量状态下发生"。曲线可由读数点 + 旁证链重建（第 6 日被抢 → 13 条锻炼静默记录 → 第 24 日 pressure 1.02，爬坡自现）。

**改法**：世界层在 `report()` 调用点，把当前写死在"（因：…）"里的信息改为**实况计算的结构化字段**，经 `extra` 传入事件簿：

```python
"readings": {
  "阳": 31.2,                # actor 事发当真阳（回光窗内另存真阳与视阳两个值）
  "pressure": 1.02,          # 若该事件有压力机制
  "阈值": 1.0,               # 被跨过的阈值的实值
  "铭记时长": 18,            # 若与某记忆相关：该记忆的年龄（日）
  "mood": {...},             # 现存情绪字段（裁剪后）
}
```

要求：
- 字段**逐事件类型定白名单**（什么 kind 带什么读数），写在配置里；没有的机制不硬塞。
- 读数必须是**事发当刻的实值**，由世界层在 report 点现算，禁止事后补估。
- 叙事层（成篇 prompt）默认**不给** readings；只有调查接口判定"此事件需深挖"时才调给 LLM。

**预期涌现效果**：史官写"他的压第 6 日起日日攀升，第 24 日溃堤"——每一个字都有数。机械感之死，始于形容词变成数字。

**验收**：
- 白名单 kind 的事件 100% 带 readings，字段值与世界内部状态一致（抽查 20 条，在 report 点旁路断言）。
- readings 不影响世界演化（同种子双跑逐字节一致——读数是观测，不是干预）。
- 事件 text 中 `（因：` 字样出现次数为 0（全簿扫描）。

### 2.3 静默日常事件入簿（draft-2 新增）

**现状缺口**：吃饭、饮水、挨饿等日常行为大多不进事件簿——侦探要重建"他饿了多少天"，簿子里查无旁证。93.7% 孤立事件与此互为表里。

**改法**：将已有但未上报的日常行为补入事件簿（首批白名单：**进食、饮水、锻炼、腐食致病、受寒受冻**——以实施时核对的实际未上报清单为准），`quiet=True`。移动、探索等逐 tick 高频行为**不入簿**（体积爆炸且无叙事价值）。

纪律：
- 静默事件**存簿但默认不进报告、不进链、不进评分**，仅调查接口可调。
- 入簿即事件，同样遵守双跑逐字节一致。

**验收**：种子 42 / 60 日，桑式案例的旁证链完整可查：被抢 → 每日锻炼记录连续可查 → 爆发，中间无断档。

### 2.4 调查接口（InquestAPI）（draft-2 新增）

**改法**：实现 `v6/shiguan/inquest.py`，对史官（及人工）提供按需调查：

```python
inquest = Inquest(ledger, snapshots, spirits)   # spirits 只读终局档案用

inquest.why(event_id) -> {
  "readings": ...,            # 该事件的现场读数
  "actor_mind": ...,          # 快照（若有）否则终局记忆档案（须标注"终局档案，事发时或已不同"）
  "旁证": [event_id...],      # 同 actor/target 的先行相关事件（按 kind 相关性规则筛选）
}
```

- 旁证筛选规则写在代码里（同当事人 + 时间窗 + kind 相关性表），不许 LLM 自由发挥。
- 终局档案替代快照时必须带**时效警告标注**（沿用 S1 出入①的纪律：终局之心非事发之心）。

**验收**：对种子 42 的 10 条白名单事件跑 `why()`，三件套齐全率、旁证 tick 有序性、时效标注齐全率均 100%。

### 2.5 世界层观测性改造（本期唯一允许的世界层改动）

> 位置：`yidao_core/spirit/*.py` 的 `report()` 调用点（约 90 处 kind）
> 性质：**只改显影，不改动力学**——行为逻辑、阈值、能量结算一行不动。

1. **去括号注释**：全部 `report(...)` 文本中的 `（因：…）` 段删除；其中有信息量的（饥饿/好斗/受辱铭记等）迁移为该事件的 readings 结构化字段。
2. **挂现场读数**：按 §2.2 白名单在 report 点现算读数，经 `extra` 传出。
3. **静默日常上报**：按 §2.3 白名单补 report 调用（quiet 标记由事件簿侧落）。

纪律：
- 每处改动必须能回答"动力学变了吗"——变了一律停工上报。
- v8 守恒与确定性测试必须照旧全绿；`text` 变更导致的口径差异在落地实录注明。
- 顺手修复 S1 遗留小瑕疵：CLI 输出目录不存在时自建（`v6/shiguan/__main__.py`）。

### 2.6 观心快照（MindSnapshot）（原 §2.2 顺延）

原设计不变，摘要重述：重要事件（白名单：死亡、渡阳、回光、战斗致伤以上、夺屋、结仇/解仇、得法、冤案相关传闻）发生当 tick，对 actor/target 做 deepcopy 快照挂到事件上：top_memories×5、pressure、代、relations、knowledge、阳。快照绝不持引用。

验收照旧：白名单 100% 带快照；快照前后灵体字段零改动（deepcopy 比对抽查 20 次）；双跑逐字节一致。

## 三、选链器：可讲述性报告（S1 已落地，本期评分校准）

### 3.1 节拍折叠 + 评分重校（draft-2 新增，S1 验收发现的问题）

**问题在案**：S1 种子 42 实测，评分长度维度数的是**原始节点数**而非**节拍数**——桑的仇恨链 15 节点（13 条重复"锻炼始"）实质是"被抢→卧薪尝胆十八日→暴起反击"的三节拍好故事，被长度惩罚压到 0.30 垫底；两节点的建造链反而 0.65 居首。榜单不校准，S3 成篇必选错链。

**改法**：
1. **节拍折叠**：链检测后、评分前，将同类连续节点折叠为节拍（13×锻炼始 → 1 个"蓄势"节拍，保留首尾节点 id 与折叠计数）。
2. **评分按节拍重算**：长度、转折、情感跨度、结局闭合四维均以节拍为单位；动机可得率改按"节拍是否可调出现场读数/快照"计算（S2 接入真值）。
3. 折叠是评分层的视图变换，**事件簿与链的原始节点不动**（考据仍指原始事件 id）。

**验收（硬指标）**：种子 42 / 60 日重出报告——桑的仇恨链（被抢第 6 日 → 反击第 24 日）进入 Top-3；纯"自悟建造→建成"类无淋雨前因的建造链退出 Top-3。四条种子报告照旧全产出，死水种子照旧明示"无可讲述之事"。

## 四、成篇器：LLM 翻译 + 考据表（S3 内容，draft-2 微调）

> 位置：新建 `v6/shiguan/writer.py`
> 依据：`pipeline/llm_client.py` 的 `LLMClient.call(system_prompt, user_prompt)` 直接复用；`configs/llm_providers.json` 既有后端直接复用，不新建 LLM 基建。

### 4.1 输入构造

成篇器吃**一条链**（不是整场事件簿）：

```
system_prompt：史官身份（侦探模型）+ 文体规范 + 禁止清单（§4.3）
user_prompt：
  【链梗概】（选链器生成的一句话，按节拍）
  【链上事件】逐条：tick/day、kind、actor、target、干净 text（无注释）
  【调查所得】成篇前由规则层对链上"关键节拍"自动调用调查接口（§2.4），
              将 readings/快照/旁证的裁剪摘要附在对应事件下
  【考据指令】每段末尾标注锚点 [E{event_id}]；文末附考据表
```

"关键节拍"的自动判定规则（如：链首、转折、链尾必查；其余看读数是否近临界）写在代码里。token 预算有界：节拍超 12 时先规则压缩。

### 4.2 输出格式（硬性，不变）

```markdown
# {标题}

{正文，每段末尾带 [E{event_id}] 锚点}

---

## 考据表
| 段落 | 锚定事件 | tick | 事件原文 |
|------|----------|------|----------|
```

### 4.3 禁止清单（写进 system_prompt，也写进校验器）

1. **不发明**：不许出现事件簿中不存在的人名、事件、物品、地点、死因。
2. **不无因果巧合**：不许写"恰好""恰巧""冥冥中"来缝合链上没有的关联。
3. **克制比喻**：每篇比喻不超过 3 处；"仿佛/似乎"全篇不超过 2 处。
4. **不预言**：不许写链尾之后的事。
5. **全知反讽仅限已记录事实**：可写"他不知道真凶另有其人"（簿中有），不可写"他不知道妻子已起杀心"（簿中无）。
6. **动机必有所本**（draft-2 新增）：凡写到"他为什么这么做"，该动机必须能指到调查所得（读数/快照记忆/旁证）中的一条；指不到的动机句 = 虚构。
7. **"不可考"是合法结局**（draft-2 新增）：调查无获时，写"其因已不可考"不仅允许，而且优先于任何推测。

### 4.4 教训在案（NVM 旧审计器）

旧 NVM 的 DeAIAuditor 把约束做成"创作约束"，越约束越僵硬。**本期约束只做考据校验，不做创作指导**——怎么写得好看是 LLM 的事，写得是不是真的是校验器的事。prompt 里不许出现"请写得跌宕起伏"这类要求，只给事实、给调查所得、给文体边界、给锚点格式。

**验收**：单链成篇 LLM 调用 = 1 次（调查与压缩都在规则层）；输出 100% 符合 §4.2 格式。

## 五、校验器：考据完备与虚构扫描（S3 内容）

> 位置：新建 `v6/shiguan/validator.py`

两级校验，全部纯规则：

1. **锚定完备性**：每段至少 1 个 `[E{id}]` 锚点；锚点 id 在该链节点集合内；考据表行数 = 正文段落数。
2. **虚构扫描**：
   - 人名白名单：正文人名 ⊆ 链上 actor/target（代称须可解析回白名单）；
   - 事件回指：考据表"事件原文"与事件簿 text 逐字一致（去注释后的干净文本）；
   - 禁词扫描："恰好/恰巧/冥冥中/命运的安排"出现即标记人工复核；
   - **动机核查**（draft-2 新增）：扫描动机句式（"因为/为了/他想/他恨…"），逐句要求其锚点事件的调查所得中存在对应证据，无证据即违规。

**重试纪律**：校验不过 → 违规清单拼入 user_prompt 重试，最多 2 次；仍不过 → 该链标记"成篇失败"写入报告，不许放行。失败的链是数据——说明事实密度撑不起一篇文，反馈给选链器调分。

## 十、世界层既定方向：能量为司机（换发动机路线）

> 性质：方向决议 + 启动门禁。**不在 v6.1 各期内实施**；满足门禁后另立需求书。
> 决议（作者拍板，2026-09-01）：能量必须是司机——能量在宇宙就是驱动力，账房要变成司机，世界才会真正活起来。这本来就是项目的立项初心（相位/势能/临界，阳极则反）；行为层的规则树是"先跑起来"阶段的临时心脏，现在正式列入更换议程。

### 10.1 目标形态

- 行为不是"每息对一张菜单核对条件"（`if 阳<32 就求助`），而是**张力差的合成解**：饿是阳的缺口形成的势阱，灵被势阱拉向食物；仇、怕、义是互相拉扯的势，行为是诸势的合成。
- 行为本身就是流，账记的本来就是流——**能量驱动让守恒账更自然，不是更矛盾**。
- 火种已在：pressure 临界涌现、回光返照、炁场凝聚均摊，都是能量在开车。换发动机是把这套原理从"几个角落"推广到"每一个行为"。

### 10.2 启动门禁（三道，全绿才许动工）

1. **仪表盘就位**：v6.1 S2 通关（现场读数+调查接口+校准后的可讲述性报告）——没有仪表盘就是闭着眼睛开飞机。
2. **故事验证**：S3 通关且卧槽测试通过——证明观测层足以评判"世界变活了没有"。
3. **基线存档**：换心前，用 S2 仪表盘对现行世界出一份基线报告（链型分布/链长/情感跨度/缺口），作为"换心是否让世界更活"的对照组。

### 10.3 重心涌现原理（S2 验收时作者之问的诊断在案）

**问题**：评分重校后榜单从"建造链刷屏"变"仇恨链霸榜"——为什么世界的叙事重心总是恩怨？真实世界的重心应该是多样的（生计、经济、欲望皆可为中心）。

**诊断（三层）**：
1. **机制层（根因）**：pressure 是当前唯一"会自己长大"的状态——被抢 +0.55、忍气吞声逐日 +0.10，过 1.0 强制释放（涌现）。恩义侧只有门槛（关系值），没有势能积累器与释放机制，故恩义链两节即终，仇恨链自我延长。生计侧的匮乏当天结清，从不过夜，长不成"重担"。
2. **世界层**：资源过于富饶，无结构性持续匮乏，"10 个顶梁柱以生计为重心"的社群无从涌现。
3. **观测层（放大器）**：可讲述性评分奖励转折与情感跨度，仇恨链天然具备——放大而非病因。

**设计准则（换发动机时执行）**：**世界的重心不是设定出来的，是"什么能积累 + 积累到何处必须释放"长出来的。** 每给一个域装上"积累器 + 临界 + 释放事件"三件套，该域即成为一个可能的叙事重心：
- 生计域：持续匮乏积累"困顿" → 临界 → 铤而走险 / 举债 / 举家迁徙
- 经济域：借贷贝易已有雏形，补利息滚动与赖账羞耻的积累
- 欲望域：求而不得日日念想 → 临界 → 争执 / 窃取 / 悟道放下

恩怨霸榜的价值：它证明了"积累→临界→释放"这台故事发动机可行。药方不是削弱恩怨，是给其他域接上同样的物理。

**追加诊断（2026-09-01 作者三问，代码实证）**：
1. **印钞机不限量（富饶之根）**：初级生产不从炁场预算出——鱼群增长式 `fish += 鱼率×(1−fish/上限)` 不含现有鱼基数（无鱼也生鱼、无捕食反馈、无季节约束，仅水温调制，world.py:609）；创世草木按湿度直接撒好，不等发芽与季节；兽群为真个体（繁殖/衰老/负伤/侏罗纪有猎杀），但田园兽无天敌。守恒账管"分钱"不管"印钱"——**富饶是水龙头拧出来的，不是涌现的**。铁律：初级生产必须入能量预算——无种不繁、捕食反馈、过季休眠；开局应贫瘠，富饶须挣来。
2. **恩怨是唯一被编程的多拍弧（霸榜之因）**：被抢后行为程序系硬编码——永存记忆 0.90、愤怒拉满、`want("变强")`、`want("报复:xx")`、谨慎漂移、锻炼循环、临界反击（conflict.py:62-66）。涌现的只是时机与胜负，剧本骨架是设计的。恩怨霸榜的完整解释：**恩怨是唯一"既有势能积累器、又被编了多拍剧本"的域**。铁律：剧本让位于物理——机制只提供"被抢→痛→积累→临界"，"变强→报复"之念须从记忆与欲望的相互作用中长出，不得 `want()` 写死。
3. **抢夺触发实况（在案）**：饥饿紧急支线 × aggr 过线 × 旁有弱者 × 随机 roll（core.py:310 + conflict.py:37）。个体缺口日日发生属合理（场富饶 ≠ 行囊富饶）；不合理在场永不被吃垮。
4. **生成态退化为运营态（2026-09-01 作者洞察，核实修订）**：天道沉默属设计正确（守道不救生，仅数值异常与炁场死寂两种情况出手；v8"安全阀静默 0 次"为 PASS 标准，勿改）。真问题在另一半：道生一至三生万物全部发生在开局（炁场极化→凝聚成形→头几日界面点生灵），此后世界只有水龙头"补充"（鱼按水温自生、草按湿度蔓延），再无"阴阳相济、从无到有"的造物——**世界从生成态退化为运营态**。与印钞机诊断同源：开局打印丰饶，则"从无到有"永不必发生。换发动机时以"造物是否持续发生"为生成态的判据之一。

### 10.4 实施铁律

- **一个域一个域换**（首域建议觅食或冲突——动机数据最足），每换一域过三道闸：守恒不破、确定性不破、可讲述性报告**不退化**（链数/长链占比/情感跨度不显著下降，上升为佳）。
- 调参方式随之改变：从"改阈值"变为"塑势场地形"。涌现系统脾气坏——可能灭绝螺旋，可能一潭死水，每次改动先小规模种子试跑再上正式验收。
- 旧规则树域保留开关（feature flag），可逐域回滚；全域换完且稳定后再删旧码。
