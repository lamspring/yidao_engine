## 〇、第一性原理与边界

### 0.1 作者第一性原理

**史官只能翻译已发生的因果，不得发明因果。**

世界（yidao_core + 灵体层）负责"发生什么"。史官负责"把已发生的事说成人能读的故事"。史官的任何一句话，都必须能回溯到事件簿里的一条真实记录。说不出来源的句子，就是虚构，就是污染——它会让世界底座的可验证性毁于一旦。

### 0.2 史官在演化回路之外

```
┌─────────────────────────────────────┐
│  世界层（yidao_core + 灵体）          │  ← 唯一真源，确定性，守恒
│  只存此刻。不存史。                   │
└──────────────▲──────────────────────┘
               │ on_event 回调（只读订阅）
               │ snapshot() / 观心字段（只读）
┌──────────────┴──────────────────────┐
│  客户端层（本期新建）                  │
│  记录仪 → 事件簿 + 观心快照            │
│  选链器 → 可讲述性报告（纯规则，零LLM）│
│  成篇器 → LLM 翻译 + 考据表           │
│  校验器 → 锚定检查 + 虚构扫描         │
└─────────────────────────────────────┘
```

**硬性边界（违者即废）**：
1. 史官全链路**零写入内核**。只允许调用只读 API：`Session.genesis/run/snapshot`、`on_event` 订阅、灵体对象只读字段。不得 import 后修改任何世界状态。
2. **世界不跑，史官不花钱**。LLM 调用只发生在成篇环节；选链、记录、校验全部是纯规则，零 LLM 成本。
3. 世界层不需要为史官改任何一行代码。如实施中发现"必须改内核才能观测"，停下来上报，不许动手——大概率是观测姿势不对，不是世界缺东西。

## 一、史官定位

史官是**全知但克制的史记作者**：

- **全知**：它订阅了全部事件，看过当事人的观心快照。它知道"赵四怀疑张三偷鱼"其实是一桩冤案，知道李四救人时心里闪过的是十年前的一个承诺。灵不知道的事，史官知道。
- **克制**：全知只用于**反讽与留白**（"他不知道，真凶另有其人"），绝不用于**发明**（不许写"他不知道，一场更大的阴谋正在酝酿"——除非事件簿里真的在酝酿）。
- **文体**：史记体 × 悬疑叙事的克制白描。短句。冷笔。把戏剧性交给事实本身的排列，不交给形容词。**禁用网文腔**（"卧槽""绝绝子""炸裂"等一律禁止），禁用空泛抒情。

## 二、记录仪：事件簿 + 观心快照

> 位置：新建 `v6/shiguan/recorder.py`
> 依据：`yidao_core/session.py` 的 `on_event(tick, pos, text, kind, actor=None, target=None, **extra)` 回调与 `snapshot()`；`v6/fishbowl.py` 的 `report()` 与 `journal` 是现成雏形，可参照但**史官自建独立事件簿**，不寄生在 fishbowl 的打印逻辑上。

### 2.1 事件簿（EventLedger）

**现状**：世界只存此刻，on_event 回调即发即弃；fishbowl 的 journal 只记了 `report()` 里拼好的文本行，结构化字段（kind/actor/target/extra）在拼接后丢失。

**改法**：实现 `EventLedger` 类：

```python
ledger = EventLedger()
session = Session.genesis(seed=..., on_event=ledger.record)
```

每条事件存结构化记录：

```python
{
  "tick": int, "day": int,          # day = tick // 每日tick数，沿用 fmt_time/day_of 的换算
  "pos": tuple | None,
  "kind": str,                       # 事件类型（战斗/死亡/建造/取火/传闻/渡阳/回光…以实际回调值为准）
  "actor": str | None,
  "target": str | None,
  "text": str,                       # 世界给出的原文（考据的一手材料）
  "extra": dict,                     # subject 等考据线索，原样保留
}
```

要求：
- **原样存录，不做任何加工**。text 字段一字不改。加工是下游的事。
- 事件簿可序列化为 JSON（`ledger.save(path)` / `EventLedger.load(path)`），同种子双跑产出的事件簿**逐字节一致**（继承世界确定性）。
- 提供按 kind / actor / target / 时间窗的查询接口，供选链器使用。

**预期涌现效果**：世界第一次有了"史"。所有下游（选链、成篇、校验、复盘、调参）都建立在这份账上。

**验收**：
- 同种子双跑，事件簿 JSON 逐字节一致。
- 事件总条数、各 kind 计数与世界 stdout 日志口径一致（抽样 3 个种子核对）。

### 2.2 观心快照（MindSnapshot）

**现状（关键缺口）**：灵的心是活的——记忆在压缩、遗忘、失真，欲望在涨落，关系在反转。**事后去观心，观的已经不是事发时的心**。若只存事件不存心，史官写"他为什么这么做"时只能靠猜，猜就是虚构。

**改法**：实现 `MindSnapshotter`，在**重要事件发生的当 tick**，抓取当事人（actor 与 target）的观心快照，挂到该事件记录上：

```python
{
  "event_id": int,
  "actor_mind": {
    "阳": float, "代": int,
    "top_memories": [...],     # 当前权重最高的若干条记忆（原样文本+权重）
    "pressure": {...},         # 现存压力/欲望字段原样
    "dna": {...},              # DNA 位点（若有外显接口）
    "relations": {...},        # 与 target 的关系值（好感/仇恨/债务/世仇标记）
    "knowledge": [...],        # 已得法技能清单
  },
  "target_mind": { ... 同上 ... }  # 若 target 是灵
}
```

要求：
- 快照只读拷贝（deepcopy），绝不持引用——持引用等于把活的心偷渡进史官，后患无穷。
- "重要事件"白名单先行：死亡、渡阳、回光、战斗（致伤以上）、夺屋、结仇/解仇、得法、冤案相关传闻。白名单写在配置里，可增删。
- 快照体积可控：top_memories 默认取前 5 条，字段裁剪白名单化，不整灵拷贝。

**预期涌现效果**：史官第一次能回答"为什么"。张三夺屋那一刀，史官手里有他当时的记忆前五条和仇恨值——写出来的动机是考据，不是文学想象。

**验收**：
- 白名单事件 100% 带快照；非白名单事件 0 快照（抽查）。
- 快照取走后世界继续运行，灵体对象无任何字段被改动（快照前后对灵做 deepcopy 比对，抽查 20 次）。
- 同种子双跑，快照内容逐字节一致。

## 三、选链器：可讲述性报告（纯规则，零 LLM）

> 位置：新建 `v6/shiguan/selector.py`
> 依据：`v6/fishbowl.py` 已有 `find_chains`（仇恨链）、`find_grace_chains`（恩义链）、`find_build_chains`（建造链）、`find_seize_chains`（夺屋链）、`find_skill_chains`（器物/取火/畜牧链）、`find_family_trees`（家族链）、`find_debt_chains`（债务链）、`find_gossip_chains`（传闻/误会链）、`find_migration_chains`（迁徙链）、`_疑案结局`。这些函数现在只吃 journal 文本行，要改造成吃结构化事件簿。

**选题原则：链优先，不是时间线流水账。**
一篇好故事 = 一条有起承转合的因果链。"第 1 天张三捕鱼，第 2 天李四建房"不是故事；"张三夺了李四的屋，李四的儿子二十年后得法归来"是故事。

**改法**：实现 `ChainSelector`，输入事件簿（+快照），输出《可讲述性报告》：

1. **链检测**：将 fishbowl 的 find_* 系列函数迁移/改造为消费 EventLedger（保留原文本输出能力，新增结构化输出：链的节点=事件 id 序列）。
2. **链打分**：每条链给一个可讲述性评分，维度至少含：
   - 长度（节点数，3~8 为佳，过短无事，过长难讲）
   - 转折数（链内 kind 变化次数，如 恩→仇→救）
   - 动机可得率（链上事件带观心快照的比例——有"为什么"的链才讲得深）
   - 情感跨度（链上是否同时含生与死、恩与仇这类对冲）
   - 结局闭合（链尾是死亡/离去/和解等闭合事件，还是悬在半空）
3. **报告输出**（Markdown + JSON 双格式）：
   - 按评分排序的链清单，每条链附：一句话梗概（规则生成）、节点事件 id 列表、评分细目
   - 全场统计：各链型数量、孤立事件比例、平均链长
   - **世界丰富度体检**：若整场跑完一条 3 节点以上的链都没有，报告必须明示"世界在此种子下无可讲述之事"及缺口在哪（如：无恩义链→互助机制冷；无冤案→传闻系统空转）

**这是本期的杀手特性**：可讲述性报告 = 世界丰富度的体检仪表盘。**史官写不出好链，不是史官的问题，是世界哪里不够丰富的信号**。以后每调一次世界参数，先跑这份报告看链变多变少，比盯 stdout 强一百倍。

**预期涌现效果**：选题从"我觉得这段有意思"变成"数据显示这条链评分最高且动机可得率 87%"。

**验收**：
- 4 个种子各跑 60 日，报告全部产出；每份报告至少给出评分 Top-3 链及其完整节点事件 id。
- 抽查 Top-1 链：链上每个节点 id 都能在事件簿中找到，且链内先后关系与 tick 序一致。
- 故意喂一个"死水种子"（生灵极少或无互动参数），报告必须输出"无可讲述之事"并指出缺口，不许硬凑。

## 四、成篇器：LLM 翻译 + 考据表

> 位置：新建 `v6/shiguan/writer.py`
> 依据：`pipeline/llm_client.py` 的 `LLMClient.call(system_prompt, user_prompt) -> tuple` 直接复用；`configs/llm_providers.json` 既有后端配置直接复用，**不新建 LLM 基建**。

### 4.1 输入构造

成篇器吃**一条链**（不是整场事件簿）：

```
system_prompt：史官身份 + 文体规范 + 禁止清单（见 4.3）
user_prompt：
  【链梗概】（选链器生成的一句话）
  【链上事件】逐条：tick/day、kind、actor、target、世界原文 text
  【当事人观心】链上带快照事件的 mind 摘要（记忆/压力/关系，裁剪后的）
  【考据指令】每个自然段末尾必须标注锚点 [E{event_id}]；全文结束附考据表
```

token 预算有界：单链事件超 12 条时先做规则压缩（合并同类连续事件，如"连续 5 日捕鱼"折成一条），压缩规则写在代码里，不许让 LLM 自己挑重点。

### 4.2 输出格式（硬性）

```markdown
# {标题}

{正文，每段末尾带 [E{event_id}] 锚点}

---

## 考据表
| 段落 | 锚定事件 | tick | 事件原文 |
|------|----------|------|----------|
| §1 | E12 | 340 | "张三夺李四之屋..." |
| ... | | | |
```

### 4.3 禁止清单（写进 system_prompt，也写进校验器）

1. **不发明**：不许出现事件簿中不存在的人名、事件、物品、地点、死因。
2. **不无因果巧合**：不许写"恰好""恰巧""冥冥中"来缝合链上没有的关联。
3. **克制比喻**：每篇比喻不超过 3 处；"仿佛/似乎"全篇不超过 2 处。
4. **不预言**：不许写链尾之后的事（"他不知道，更大的风暴将至"——除非事件簿里风暴真的来了，那它应该在链上）。
5. **全知反讽仅限已记录事实**：可以写"他不知道真凶另有其人"（因为事件簿里有真凶），不可以写"他不知道妻子已起杀心"（除非快照/事件里真有）。

### 4.4 教训在案（NVM 旧审计器）

旧 NVM 的 DeAIAuditor 把约束做成了"创作约束"，越约束越僵硬。**本期约束只做考据校验，不做创作指导**——怎么写得好看是 LLM 的事，写得是不是真的，是校验器的事。prompt 里不许出现"请写得跌宕起伏"这类创作要求，只给事实、给文体边界、给锚点格式。

**预期涌现效果**：产出的故事读上去是文学，拆开看每一句都是账。

**验收**：
- 单链成篇的 LLM 调用次数 = 1（压缩在规则层完成）；重试见 §五。
- 输出 100% 符合 §4.2 格式（格式不符直接判废重试，不进入校验器）。

## 五、校验器：考据完备与虚构扫描

> 位置：新建 `v6/shiguan/validator.py`

**改法**：实现两级校验，全部纯规则：

1. **锚定完备性**：正文每个自然段至少 1 个 `[E{id}]` 锚点；每个锚点 id 必须在该链的节点事件集合内；考据表行数 = 正文段落数。
2. **虚构扫描**：
   - 人名白名单：正文出现的所有人名 ⊆ 链上事件的 actor/target 集合（允许代称如"李四之子"，但代称必须能解析回白名单内的灵——解析规则：家族链可查的称谓）。
   - 事件回指：考据表"事件原文"列必须与事件簿 text 逐字一致。
   - 禁词扫描："恰好/恰巧/冥冥中/命运的安排/殊不知（后接未记录事实）"出现即标记人工复核。

**重试纪律（有界）**：校验不过 → 把违规清单作为反馈拼入 user_prompt 重试，**最多 2 次**；仍不过 → 该链标记"成篇失败"写入报告，**不许放行**。失败的链是数据，不是垃圾——它说明这条链的事实密度撑不起一篇文，反馈给选链器调分。

**验收（六条总验收见 §七）**。

## 六、分期

### S1：事件簿 + 可讲述性报告（纯规则，零 LLM）
- 内容：§2.1 EventLedger + §三 ChainSelector（含报告）
- 通关：§2.1 与 §三的全部验收项
- 说明：**S1 落地后叫我验收**。这份报告本身就是世界丰富度仪表盘，哪怕 LLM 一行不调，它已经值回票价。

### S2：观心快照记录仪（纯规则）
- 内容：§2.2 MindSnapshotter，并入事件簿
- 通关：§2.2 全部验收项；S1 报告升级——链打分的"动机可得率"列从 0 变为真实数据

### S3：LLM 成篇 + 考据表 + 校验器
- 内容：§四 writer + §五 validator
- 通关：§4/§五全部验收项 + §七总验收 1-4
- 说明：默认后端 deepseek（按 configs/llm_providers.json 现状）；单链成篇成本写入落地实录（tokens 数、耗时、费用估算）

### S4：连载模式（观察日记体）
- 内容：多日连跑，史官按"日更"产出编年连载；链跨日续接（今日之链是昨日之链的下一节）
- 通关：同一世界连续 60 日产出 ≥ 10 篇，篇间引用一致（前篇锚点在后篇可复用，人物关系续接无矛盾——校验器加"跨篇一致性"检查）
- 说明：**S4 开工前必须先过"卧槽测试"**（§七-1），单篇不过卧槽，连载只是批量生产平庸。

## 七、总验收（六条）

1. **卧槽测试**：S3 产出的第一篇成篇，拿给不知情的读者看，读完结尾的反应是"卧槽"。此条由作者（用户）人工判定，一票否决。
2. **考据完备 100%**：每段有锚，锚锚有账，考据表原文与事件簿逐字一致。
3. **虚构扫描通过**：人名白名单零越界，禁词零出现，代称全可解析。
4. **确定性不破**：同种子同事件簿（逐字节一致）；成篇文本允许 LLM 温度差异，但**选中的链、链上节点、考据表骨架**必须相同。
5. **零写入内核**：史官全链路运行前后，对世界做状态哈希比对一致；grep 史官全部代码，无对 yidao_core / 灵体对象的任何赋值语句（只读 import）。
6. **成本有界**：单场 60 日世界，LLM 调用 ≤ 链数（每链 1 次成篇 + ≤2 次重试）；规则层（记录/选链/校验）零 LLM 成本，实测耗时写入实录。

## 八、不做清单（本期）

- **不做播放器 / 图形界面**：史官产出 Markdown，渲染是以后的事。
- **不改世界层一行代码**：发现观测不到的东西，上报，不动手。
- **不做实时史官**（边跑边写）：先死后著——世界跑完、事件簿落盘、再选链成篇。实时化是 v6.2 以后的事。
- **不做读者互动 / 多视角叙事**：单一全知史官视角。多视角（灵的限知视角）留给以后。
- **不接 P3 遗留项**（对数化 / 1/f 粉噪 / 幂律优先连接）：那是世界层的事，与本期正交。
- **不做 prompt 里的创作指导**：理由见 §4.4。
