# 易道引擎 · 趟雷记录

> 从烂到能用的全过程，每个坑踩过一次就够了。

---

## 一、世界观配置：只给骨架，不给血肉

**踩过的坑**：最早把暗线身份（入殓师/守灵人/赌客）写进 `entity_context`，LLM 直接在第一段写"后来他得知这人叫林小意，职业栏里写着戏剧演员"——上帝视角暴露。

**正确做法**：
- 实体 description 只写可观察表象（年龄、体型、动作习惯），不写暗线身份、性格判断、人物关系
- `entity_context` 只描述所有人可见的信息
- "田税一万斤"属于世界物理常数，可以给；"多疑缜密"属于人物判断，不能给
- 叙事规则里加"人物性格和身份只能通过行为和对话暗示——禁止作者旁白"

---

## 二、实体标签：可观察描述，不是名字也不是代号

**踩过的坑**：
- 第一版：标签是"角色B""角色C"→ LLM 看不懂，自己发明了"赵老倌""钱六"等完全无关的角色
- 第二版：标签是空字符串→ LLM 数据里分不清谁是谁
- 第三版：标签是"个子最高的那个""蹲在田边的年轻女人"→ LLM 终于知道这些数据说的是谁了

**正确做法**：
实体标签必须是主角沈青**此刻能看到什么**：`"个子最高的那个" "蹲在田边的年轻女人" "一直搓衣角的瘦子"`。这些是可观察描述，不是名字。名字必须通过对话或自我介绍在叙事中自然引入。

## 三、意象追踪器：网格×实体的状态快照，不是人名列表

**踩过的坑**：
- 最早用嵌套 JSON 格式让 LLM 输出 → LLM 完全理解不了，每次都写错 key
- 改成 JSON 后 LLM 输出 `"name": "铁三"` 把人物名当意象名
- 最后改成 markdown 列表 `- 意象名 | 状态 | 重要级 | 类别 | 变化` → LLM 能稳定输出了

**正确做法**：
- LLM 输出格式用 markdown 列表而非 JSON——它更擅长
- Python 用 `split('|')` 解析，比正则更稳健
- 意象名不能是人名——解析器自动过滤以角色名为意象名的条目
- 每个实体在每个网格至少 2 条意象（人均≥2 条检查）
- 意象追踪器管世界观连续性，prev_summary 管剧情衔接——两者分工不同

---

## 四、章节衔接：Delta 压缩概述，不是截尾

**踩过的坑**：
- 最早取最后 200 字作 prev_summary → 截到"像是从地下传上来的"这种碎片，LLM 接不上
- 改成取最后两句诗"那样子，像一条还没有流过来的希望"→ LLM 拿到诗句不知道场景，从头重演
- ch2 开头重演了 ch1 的全部事件（税官宣布规则、挖渠）

**正确做法**：
- 每章结束后调 LLM 生成 2-3 段合并概要（已有前情 + 本章正文）
- 下章只读上一章的合并概要（已包含全历史），不逐章累积
- 时间过渡指令："务必先交代时间过渡（第二天早上/当夜），禁止重复已发生的事件"

---

## 五、LLM Backend：多后端自动降级

**踩过的坑**：DeepSeek SSL 狂断连，换 MiMo 后又遇到 Python requests 的 TLS 握手不兼容（curl 能通但 requests 不通）。

**正确做法**：
- 三个后端：requests → httpx → curl，自动降级
- 每个 provider 独立配置 `verify_ssl` 和 `transport`
- DeepSeek：`verify_ssl=true, transport=requests`
- MiMo：`verify_ssl=false, transport=httpx`

## 六、叙事提示词：铁律在前，写在后

**踩过的坑**：LLM 反复犯同样的错——名字堆砌出场、时间跳跃、暗线身份暴露。

**正确做法**：
- 提示词里"叙事铁律"放最前面，用数字编号
- 禁止句式："不是……是……"（上限 2 次）、"后来他得知"
- 时间跳跃：必须写"第二天早上"等明确过渡
- 角色出场：名字必须通过对话或场景自然引入
- 每次跑完质量快检扫描这些问题

---

## 七、Tick 数：750 是甜点

| tick | 卦变 | 叙事质量 |
|------|------|---------|
| 50 | 0 | LLM 完全自编角色，不理引擎数据 |
| 250 | ~18 | 有卦变但剧情浅 |
| 500 | ~2-20 | 不够推动完整弧线 |
| 750 | ~20-30 | 够一轮完整冲突+转折 |
| 1500 | ~30 | 多出的是氛围细节，无实质新增 |

750 tick，快照间隔 max(50, 750//10)=75，共 11 帧。

## 八、多网格架构：配置驱动，内核不动

**踩过的坑**：一开始设计被丰收税局具体设定绑死（天道=恶灵规则、人界=玩家行为）。

**正确做法**：
- `kernel.py` 纯数学，不动
- `cosmos.py` 管理 N 个 World 实例，配置驱动
- `entity.py` 跨网格实体，持有网格位置+卦历史
- `grid_semantics` 等世界术语全部在 JSON 配置里，`_generate_chapter` 动态读取
- 大唐天宝 JSON 换皮只需改配置文件，引擎代码零改动

---

## 九、意象提取的 JSON 死胡同

LLM 根本不适合输出嵌套 JSON。尝试过的格式：
- `{"grid": {"entity_id": [...]}}` → LLM 写成 `{"e2@ren": [...]}`
- 加 ````json` 代码块 → 引号不闭合
- 加"只输出JSON" → `{...` 后面还有 Markdown 尾巴

最终方案：markdown 列表 + Python `split('|')` 解析，LLM 输出稳定，解析容错高。
