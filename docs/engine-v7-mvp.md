# 《易道引擎》v7 重构设计稿——鱼缸 MVP 与引擎预留

> 本文档是 v7 重构的总设计稿。主线：**把鱼缸做成作者自己好用的 MVP 样品**；
> 副线：按分层原则整理内核，给未来游戏引擎**留渡口**——不建墙，也不建桥。
>
> 底座哲学见 `engine-v6-lingti.md` 附录《宇宙底座第一律》，本文档是它的工程化。

---

## 一、决策记录（2026-08-27 作者拍板）

1. **核内标识符继续中文。** 内核是说给自己听的母语；对外别名等真有外部用户那天再说。
2. **灵体层组件-OOP，不上 ECS。** 行为已稳定，不为时尚早的架构付两次重构费；ECS 留待性能证据。
3. **3D：格子维度参数化留接口；先 2D，后试 3D。** 算子无量纲（扩散/极化/凝聚在任意维成立），首期仍跑 2D。
4. **联机：预留，不动。** 确定性已天然具备 lockstep 条件，但首期明确不做。
5. **叙事层（LLM 史官）作为订阅客户端接入。** 订阅事件流编织叙事，彻底坐实"LLM 不在演化回路内"。
6. **优先级：鱼缸 MVP > 引擎化。** 引擎化整体列入"以后"，本期只为它留接口形状。

## 二、分层架构（国境线）

```
┌─────────────────────────────────────────────┐
│ 客户端层（核外）                               │
│   fishbowl 终端文字流 · LLM 史官 · 回放查看器   │
├─────────────────────────────────────────────┤
│ L4 接入层 api（预留最小实现）                   │
│   Query / Command / Subscribe / Snapshot      │
├─────────────────────────────────────────────┤
│ L3 调度层 session                             │
│   变速时钟 · 事件总线 · 存档 · 种子权威          │
├─────────────────────────────────────────────┤
│ L2 灵体层 spirit                              │
│   组件（纯数据）+ 系统（纯逻辑）                │
├─────────────────────────────────────────────┤
│ L1 物质层 matter                              │
│   水土草器物建筑——全是炁场的凝结态              │
├─────────────────────────────────────────────┤
│ L0 炁场层 qi（新底座）                         │
│   常驻能量场 · 阴阳姿态 · 凝聚/逸散/归还        │
│   守恒结算器 · 越界账 · 相图                   │
└─────────────────────────────────────────────┘
天道 watchdog：熵计监测、留痕介入（横切 L0–L2）
```

铁律（继承并强化）：
- 依赖只许向下；核内零渲染、零 print、零无种子随机。
- 客户端不可直写核内状态——Command 是唯一写入口，一切变化以事件流出。
- 世界无史：核内只存此刻；观测笔记、回放、多档管理全在客户端。

## 三、L0 炁场层设计（宇宙第一律的代码化）

### 3.1 数据结构

每格三件套：

```python
energy      # float 场能总量（处处皆能，无空格）
disposition # float 阴阳姿态（-1 纯阴 … 0 冲和 … +1 纯阳）
condensate  # 凝结态引用（None 或指向一个物质对象）
```

维度参数化：格子邻居表由 `ndim` 生成（2D=8 邻，3D=26 邻），算子只遍历邻居表——这是留给 3D 的渡口。

### 3.2 演算算子（全部是"转移"，没有"增减"）

| 算子 | 语义 | 对应原话 |
|------|------|----------|
| `diffuse` | 能量向邻域均流 | 炁向邻域均流 |
| `interact` | 阴阳姿态相交，更新当地姿态 | 阳撒到 A 点，与 A 点之阴相交 |
| `condense` | 阴阳相容达阈 → 凝结成形（查相图） | 阴阳相容，诞生新的有形之物 |
| `dissipate` | 凝结物按材质速率就地归还（连续） | 洒水壶：走到哪撒到哪 |
| `collapse` | 阳尽形坏，阴一次性就地归还 | 倾覆：阴尽数回归环境 |

### 3.3 守恒结算器与越界账

- 所有算子**只产出转移单** `(from, to, amount, kind)`，由结算器统一执行；
- 出流按格封顶：承诺总量超过存量则按比例压缩（修掉水流复制式守恒 bug 的统一机制）；
- 越界注入（种子涨落 / 点化 / 天道 stir）走同一通道，但记入 `越界账`；
- 守恒断言收紧为：**总量严格守恒 ± 留痕越界账**（取代"漂移 < 50%"）。

### 3.4 相图（数据驱动，首版极小）

`configs/matter_phases.json`：凝结条件 → 产物。首版只收三四条（草、苔、土肥），验证"逸散即播种"闭环后再扩——黄金、熔岩是相图上的稳定区，不枚举。

## 四、L2 灵体层：组件化拆分方案

`spirit.py`（3471 行）拆为**组件（纯数据 dataclass）+ 系统（纯逻辑函数/类）**。
铁律：**行为不变**——拆分前后多种子逐字节一致，25 项不变量全过。

组件（数据）：
`Body`（阳/水分/力量/body_curve/寿数）· `Genome`（dna）· `Memory`（记忆列表/序）· `Mood`（心情/压力）· `Desire`（goals）· `Knowledge`（知识/经验/熟练）· `Property`（行囊/屋田/债务）· `Relations`（亲缘/伴侣/关系缓存）· `SocialMemory`（传闻/声望/已知情报）

系统（逻辑，按 spirit.py 现有方法族归拢）：
`感知`（感知/生疑/同悼）· `生计`（觅食/饮水/渔猎/采集）· `学习`（积学/传授/家传/摸器悟法）· `社交`（交谈/传闻/对质/人情）· `争斗`（抢夺/报复/庇护/战斗/涌现）· `营建`（营建/凿井/农事/百工/畜牧）· `婚育`（婚配/诞育/幼年/成年/寿终/善后）· `徙居`（察荒/迁徙/选址）· `安身`（栖身/安眠/淋雨/受冻/取火/烹制）

## 五、鱼缸 MVP 功能清单（"给我自己用"）

已有：终端事件流、`--inspect` 观心、点化 API、27+ 类事件、终局摘要。

待做（M3 核心）：

1. **变速时钟**：暂停 / 1× / 8× / 64×，交互式按键控制；
2. **存档/读档**：全量序列化（npz+json），核内覆盖式单档 + 客户端手动另存；加载后续跑逐字节一致（验收项）；
3. **点化入 UI**：观测中指定坐标注入阳种（已有 `seed_at`，接进交互循环）；
4. **观心强化**：记忆/欲望/学习进度/DNA 禀赋/传闻版本的"X 其人"——历史只存在于角色心中，观心是唯一读史界面；
5. **事件过滤订阅**：最小事件总线（按类/按地/按人过滤），替代单回调；
6. **LLM 史官客户端**（可选开关）：订阅事件流 → 悬疑推理级严谨叙事；只能翻译已发生的因果，不得发明。

## 七、引擎预留清单（现在不做，但不封死）

- **L4 API 形状**：Query / Command / Subscribe / Snapshot 四动词，M3 的鱼缸客户端只经由此面访问内核——鱼缸就是 L4 的第一个客户与试金石；
- **内容目录约定**：`configs/` 收相图/技能/配方定义，为将来数据化铺路；
- **lockstep 确定性**：显式种子 + 双跑逐字节一致的传统不变；
- **分块 LOD 接口**：World 边界交换协议留注释位，不实现。

---

## 八、不做清单与风险

**本期不做**：ECS、联机、Web/图形界面、任务/成就系统、英文 API、多世界。

**风险**：
- 炁场层改写牵动 `world.py` 全场——采用绞杀者模式：炁场层先与现有场**并行存在**（水/草暂以镜像方式同步），守恒断言双向对账，稳定后再切换，老路径整段删除；
- 守恒结算可能改变水文手感（降雨地方性、干湿交替）——M1 验收含"手感对照"：同种子关键统计（降雨场次/草覆盖率/存活数）与基线并列呈现，人眼确认不变味；
- 组件化拆分的最大风险是"顺手改逻辑"——M2 只许搬代码，不许改数值。
