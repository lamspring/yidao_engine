# 《易道动态世界引擎》v4.0 — YDWE (Yi Dynamic World Engine)

基于《易经》阴阳爻、先天八卦、六爻生命周期、《道德经》反者道之动设计的**自演化世界模拟器**。

**这不是游戏引擎。这是东方信息宇宙模型的计算内核。**

---

## 核心哲学

> **世界不是物体集合，而是阴阳流动形成的暂时稳定结构。**

- **阳 (气象为正)**：制造差异，扩张显化，加速分化
- **阴 (气象为负)**：消化差异，融合回归，减速沉淀
- **万物**：阴阳在局部对抗、交融、达成暂时平衡的"驻波"
- **爻不是状态，而是趋势**：描述变化方向，而非固定属性

---

## 象-气-势三才模型

本引擎的核心架构暗合《道德经》"道生一，一生二，二生三，三生万物"的生成论：

| 维度 | 场名 | 代号 | 哲学定位 |
|------|------|------|----------|
| **象** | 卦象场 | `S` | 万物之**形**。六十四卦是世界的结构骨架，是"负阴而抱阳"的暂时稳定态。 |
| **气** | 气象场 | `T` | 万物之**交**。不是被动算出的"趋势指标"，而是一个主动的、有惯性的、在世界中真实流动的实体。它是"冲气以为和"的那个**气**，是象与势之间的交通媒介，使阴阳得以交感、转化。 |
| **势** | 反向势能场 | `V` | 万物之**待发**。长期稳定中积累的"即将反转"的能量，是"反者道之动"的量化体现。 |

**P（六爻生命周期）**则是时间在三才身上刻下的年轮，记录每个局部结构经历了多少"气象流动"而走向成熟或衰变。

> **为什么 `T` 不直接由 `S` 算出，而要作为独立状态场存在？**
>
> 因为"象"不等于"气"。离卦的结构确实蕴含"外显内虚"的本性（D），但当下吹拂它的"气"可以是顺其本性的南风，也可以是逆势的寒流。`T` 的惯性（α·T）正是"气象"的记忆与延续——它让世界的变化有**质感**，而非卦象一换、万物瞬变的僵硬响应。`T` 是使"反者道之动"能够发生的过程本身。

**系统禁止：**
- 随机数（演化完全确定性）
- 固定对象/实体/Agent（纯场模型）
- 静态数据库（必须是活系统）
- 模块化"扩展文明/角色/剧情"（上层只能做涌现解释，不能做状态写入）

## 系统架构（四层）

| 层级 | 名称 | 对应 | 职责 |
|------|------|------|------|
| Layer 0 | 太极源层 (道) | 全局平衡 | `DaoController` 监测全局趋势能量与阳爻比例，动态调节阈值 V，体现"无为而治" |
| Layer 1 | 两仪爻场层 | CPU | 四场耦合演算：卦象场 + 气象场 + 六爻生命周期场 + 反向势能场 |
| Layer 2 | 八卦协议层 | 结构/行为 | 八种纯卦定义八种基本"协议"（承载、激变、深渊、渗透、止界、显文明、交换、创序） |
| Layer 3 | 万物涌现层 | 渲染/现象 | 将卦场统计翻译为世界描述与六爻语义（只读解释，不写状态） |

## 核心演算（一息之内）

对每个格点执行：

```
S  = 当前卦 (0-63)
T  = 气象场阴阳流向 (-1~+1)         # 不是"趋势指标"，而是真实流动的"气"
P  = 六爻生命周期相位 (0~1)
V  = 反向势能 (>=0)

E  = WuXing_Resonance(3×3邻域9卦)     # 外感：五行交感（替代旧版XOR）
D  = Bagua_Protocol_Drive(S)           # 内化：八卦协议本征驱动力
T' = α·T + (1-α)·E + β·D + Dao_Bias  # 气象演化：冲气流动，阴阳交感
P' = P + γ·|T'| · (1 + κ·V) · C      # 六爻推进（C=冷却期调制）
V' = V + acc(T') + extra(stable_age) # 反向势能积累

if P' >= 1.0:                          # 上爻反转：生命周期终结
    S' = CuoGua(S)                     # 错卦（六爻全变，最彻底反向）
    P' = 0; V' = 0; T' = -T'·0.25

elif V' > V_thresh:                    # 势能释放：内在矛盾爆发
    if P < 0.30:  S' = HuGua(S)        # 初爻期 → 互卦（内部矛盾显性化）
    elif P < 0.60: S' = ZongGua(S)     # 中爻期 → 综卦（结构翻转）
    else: S' = YaoBian(S, pos)         # 后爻期 → 单爻变
    V' = 0
```

## 关键技术特点

1. **纯交感驱动**：演化过程**零随机数**。初始条件亦确定性生成（无极→太极→两仪→四象→八卦）。
2. **五行交感矩阵**：64卦之间的相互作用由先天八卦的五行生克关系（相生/相克/通气/对冲）决定，替代了旧版的简单 XOR。
3. **六爻生命周期**：任何局部结构强制经历"初爻萌芽→二爻稳定→三爻过界→四爻碰撞→五爻主导→上爻极化→反转"的完整周期。
4. **反向势能**：长期稳定的区域自动积累"即将反转"的势能，体现《道德经》"反者道之动"。
5. **道控制器**：监测全局气象能量与阳爻比例，动态调节势能阈值 V，体现"天之道，损有余而补不足"。
6. **四种卦变指令**：错卦（全面反转）、综卦（结构翻转）、互卦（内化显现）、单爻变（局部调整）。
7. **六爻语义解释**：每个协议在六爻不同阶段有对应的涌现语义（如"离-初爻：星火初燃"→"离-上爻：明极反晦"）。

## 运行方式

### 交互式可视化（推荐）
```bash
python main.py
```
- 默认 32×64 世界，实时彩色终端渲染
- `◆` = 刚发生卦变的位置
- `●` = 势能濒临爆发的位置
- 按 `Ctrl+C` 停止

### 参数调整
```bash
python main.py --height 64 --width 64 --delay 0.03
```

### 无界面快速运行
```bash
python main.py --headless --steps 1000 --height 64 --width 64
```

### 诊断模式（查看气象场与势能场）
```bash
python main.py --diagnose --steps 200
```

## 多 AI 协作规范

**错误的协作方式（禁止）：**
- AI A "扩展文明模块"
- AI B "扩展角色模块"
- AI C "扩展剧情模块"

这会把系统拉回对象化、模块化的西方架构，与《易》的感应哲学背道而驰。

**正确的协作方式：**
所有 AI **只读取同一份场快照**，各自做**涌现解释**：

| AI | 输入 | 输出 |
|---|---|---|
| 考古学家 | `history` 时序序列 | "此区域过去 300 息经历了坎→离的极化，意味着水火既济式的文明爆发" |
| 地理学家 | `gua` 空间分布 | "此地艮卦浓度高，形成止界，可解释为山脉/禁区/法律凝固带" |
| 心理学家 | `trend`(气象) + `potential` | "此区域阳爻 78% 且气象动荡，对应集体意识中的躁动/革命前兆" |
| 诗人 | 整体 `snapshot` | "天雷无妄，密云不雨，万物在静止中等待第一滴雨" |

**核心原则：AI 不拥有状态。AI 只是场的解释者。**

## 设计约束（不可违背）

1. **底层禁止随机**：`World.tick()` 内不得出现任何随机数生成器。
2. **初始条件确定性**：`_init_field()` 必须从确定性的几何/代数结构生成，禁止 `rng.integers()`。
3. **上层禁止写入**：任何解释层（renderer、外部 AI）只能调用 `get_snapshot()` 和 `analyze_region()`，不得修改 `gua`、`trend`(气象)、`phase`、`potential`。
4. **禁止对象化涌现**：不得在世界内核之上叠加 `Civilization`、`Character`、`Event` 等对象系统。文明、角色、历史只能是**卦场统计的语义翻译**。
5. **变化必须源于交感**：任何演化规则必须能用"阴阳交感、五行生克、六爻周期、穷极则变"解释。
